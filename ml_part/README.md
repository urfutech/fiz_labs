# Гибридная проверка выводов лабораторных работ

Проект для автоматической проверки выводов студентов по лабораторной работе №1 и поиска подозрительных совпадений между работами.

В основе лежит гибридный подход:

- **регулярные выражения** извлекают числовые значения: плотность, погрешности массы, диаметра и высоты;
- **таблица плотностей** определяет материал по найденной плотности;
- **формула погрешностей** вычисляет, какая величина даёт главный вклад в общую погрешность;
- **локальная LLM** через `llama.cpp` проверяет смысловые формулировки:
  - измерены ли масса, диаметр и высота;
  - сказано ли, что определена плотность;
  - назван ли материал;
  - указан ли главный вклад погрешности;
- **антиплагиат** считается отдельно:
  - локальные эмбеддинги через `llama.cpp`;
  - лексический анализ через `TF-IDF`.

Основной скрипт проекта — `hybrid_lab1_checker.py`.

## Проверяемые критерии ЛР 1

Скрипт проверяет три критерия.

### Критерий 1

Студент должен сформулировать, что:

- измерены масса, диаметр и высота образца;
- на основе этих измерений определена плотность.

### Критерий 2

По значению плотности должен быть верно идентифицирован материал.

Например:

| Материал | Плотность, кг/м³ |
|---|---:|
| Алюминий | 2700 |
| Бронза | 8700–8900 |
| Железо | 7870 |
| Золото | 19300 |
| Латунь | 8400–8700 |
| Сталь | 7500–7900 |
| Медь | 8930 |
| Титан | 4500 |

### Критерий 3

Должно быть определено, погрешность какой величины даёт главный вклад в общую погрешность результата:

- масса;
- диаметр;
- высота.

Для плотности цилиндра используется вклад:

```text
масса:      ε_m²
диаметр:    (2 * ε_d)²
высота:     ε_h²
```

## Требования

- Python 3.9+;
- зависимости из `requirements.txt`:
  - `pandas`, `scikit-learn`, `numpy` — таблицы и векторизация;
  - `huggingface_hub` — скачивание модели;
  - `llama-cpp-python` — локальный запуск GGUF-модели;
  - `sentence-transformers` — только для скрипта `anti-plagiarism.py`.

Модель автоматически скачивается с Hugging Face при первом запуске (около 2 ГБ) в папку `models/`.

Если `llama-cpp-python` не установлен, скрипт не падает: он печатает предупреждение и продолжает работать на регулярных выражениях и лексическом антиплагиате.

## Запуск

Базовый запуск:

```bash
python hybrid_lab1_checker.py lab_num1.json
```

Результат будет выведен в консоль.

Тестовый набор из 15 выводов:

```bash

```

```bash
python hybrid_lab1_checker.py lab_num1.json --output lab1_report.csv
```

## Основные аргументы командной строки

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `json_file` | — | Входной JSON-файл вида `{ "ФИО": "текст вывода" }` |
| `--model-repo` | `Qwen/Qwen2.5-3B-Instruct-GGUF` | Репозиторий модели на Hugging Face |
| `--model-file` | `qwen2.5-3b-instruct-q4_k_m.gguf` | Имя GGUF-файла |
| `--model-dir` | `models` | Локальная папка для хранения модели |
| `--chat-format` | — | Например `chatml`; обычно не нужен, если модель содержит шаблон |
| `--n-gpu-layers` | `0` | Сколько слоёв вынести на GPU (`0` — только CPU) |
| `--n-ctx` | `4096` | Размер контекста модели |
| `--allow-weight-as-mass` | выключен | Считать слово «вес» признаком массы |
| `--use-screen` | выключен | Включить эмбеддинг-скрининг до LLM |
| `--screen-threshold` | `0.15` | Порог скрининга (сильно зависит от модели) |
| `--embedding-prefix` | — | Префикс для эмбеддингов, если модель его требует |
| `--no-plagiarism` | выключен | Не считать антиплагиат |
| `--no-llm` | выключен | Не использовать LLM для смысловых признаков |
| `--no-model` | выключен | Не загружать модель вообще |
| `--sem-threshold` | `0.75` | Семантический порог плагиата |
| `--lex-threshold` | `0.45` | Лексический порог плагиата |
| `--llm-retries` | `2` | Число повторных попыток получить валидный JSON от LLM |
| `--allow-verbal-dominant` | выключен | Засчитывать словесный главный вклад, если нет числовых погрешностей |
| `--output` | — | Сохранить итоговую таблицу в CSV |

## Примеры запуска

### Строгий режим

```bash
python hybrid_lab1_checker.py lab_num1.json
```

В этом режиме:

- слово «вес» не считается массой;
- если нет числовых погрешностей, главный вклад не засчитывается.

### Мягкий режим

```bash
python hybrid_lab1_checker.py lab_num1.json \
    --allow-weight-as-mass \
    --allow-verbal-dominant
```

В этом режиме:

- «вес» может быть засчитан как масса;
- словесный главный вклад может быть засчитан, если нет числовых погрешностей.

### Без антиплагиата

```bash
python hybrid_lab1_checker.py lab_num1.json --no-plagiarism
```

### Без LLM

```bash
python hybrid_lab1_checker.py lab_num1.json --no-llm
```

В этом случае остаются:

- регулярные выражения;
- таблица материалов;
- формула погрешностей;
- лексический антиплагиат;
- упрощённые текстовые проверки.

### Только детерминированный режим

```bash
python hybrid_lab1_checker.py lab_num1.json --no-model --no-plagiarism
```

Модель вообще не скачивается и не загружается — работают только regex и TF-IDF.

## Модель по умолчанию

По умолчанию используется:

```text
Репозиторий: Qwen/Qwen2.5-3B-Instruct-GGUF
Файл:        qwen2.5-3b-instruct-q4_k_m.gguf
Каталог:     models/
```

Модель скачивается в `models/` при первом запуске.

### Использование другой модели

Модель можно поменять через аргументы командной строки или переменные окружения. Аргументы командной строки имеют приоритет.

#### Через аргументы

```bash
python hybrid_lab1_checker.py lab_num1.json \
    --model-repo Qwen/Qwen2.5-1.5B-Instruct-GGUF \
    --model-file qwen2.5-1.5b-instruct-q4_k_m.gguf
```

#### Через переменные окружения

**Linux / macOS, bash**

```bash
export LLAMA_MODEL_REPO="Qwen/Qwen2.5-1.5B-Instruct-GGUF"
export LLAMA_MODEL_FILENAME="qwen2.5-1.5b-instruct-q4_k_m.gguf"
export LLAMA_MODEL_DIR="models"

python hybrid_lab1_checker.py lab_num1.json
```

**Windows PowerShell**

```powershell
$env:LLAMA_MODEL_REPO="Qwen/Qwen2.5-1.5B-Instruct-GGUF"
$env:LLAMA_MODEL_FILENAME="qwen2.5-1.5b-instruct-q4_k_m.gguf"
$env:LLAMA_MODEL_DIR="models"

python hybrid_lab1_checker.py lab_num1.json
```

Также поддерживаются переменные:

| Переменная | Назначение |
|---|---|
| `LLAMA_CHAT_FORMAT` | Шаблон чата (например `chatml`) |
| `EMBED_PREFIX` | Префикс для эмбеддингов |
| `HF_TOKEN` | Токен Hugging Face для моделей с доступом по запросу |

## Антиплагиат

Антиплагиат работает в два слоя.

### 1. Лексический слой

Используется:

```text
TF-IDF
char_wb
ngram_range = (3, 5)
```

Хорошо ловит дословные совпадения.

### 2. Семантический слой

Используются локальные эмбеддинги через `llama.cpp`.

Хорошо ловит смысловую близость текстов.

### Пороги

По умолчанию:

```text
--sem-threshold 0.75
--lex-threshold 0.45
```

Для небольших моделей семантический порог обычно нужно подбирать вручную.

Рекомендации:

```text
0.65–0.75 — мягкая проверка
0.75–0.85 — умеренная проверка
0.85+     — строгая проверка
```

## Интерпретация результата

В итоговой таблице будут примерно такие столбцы:

| Столбец | Значение |
|---|---|
| `Студент` | Имя студента |
| `К1: измерения+плотность` | Выполнен ли первый критерий |
| `К2: материал` | Выполнен ли второй критерий |
| `К3: главный вклад` | Выполнен ли третий критерий |
| `Плотность` | Найденная плотность |
| `Табличный материал` | Материал, определённый по таблице |
| `Материал студента` | Материал, названный студентом |
| `Заявленный вклад` | Что студент назвал главным вкладом |
| `Расчётный вклад` | Что посчитал скрипт |
| `Скрин` | Скоринг текста |
| `Плагиат` | Есть ли подозрительные совпадения |
| `Зачёт` | Итоговый зачёт |
| `Причины` | Почему критерии не выполнены |

## Важные замечания

### 1. Слово «вес»

По умолчанию скрипт не считает слово «вес» признаком массы.

Если нужно мягче:

```bash
--allow-weight-as-mass
```

### 2. Главный вклад погрешности

- Если есть числовые погрешности массы, диаметра и высоты, скрипт считает главный вклад по формуле. Заявленный студентом вклад должен совпадать с расчётным.
- Если числовых погрешностей нет, по умолчанию критерий не засчитывается.
- Чтобы засчитывать словесный вывод, используйте `--allow-verbal-dominant` — такие работы помечаются с пометкой «требуется проверка».

### 3. Плагиат

Подозрение на плагиат не влияет автоматически на зачёт по критериям — это отдельный сигнал для преподавателя.

### 4. Пустые тексты

Пустые или слишком короткие тексты автоматически получают:

```text
Зачёт = НЕТ
```

## Ограничения

Текущая версия ориентирована на **ЛР 1**.

Для ЛР 8 и ЛР 9 нужно добавить отдельные проверки.

### ЛР 8

- определена молярная масса и плотность воздуха;
- выполнено сравнение с 29 г/моль;
- при отличии больше 10% объяснены причины.

### ЛР 9

- определены момент инерции шкива и крестовины;
- определён момент силы трения;
- отмечено, что линейная зависимость момента силы от углового ускорения подтверждает основной закон динамики вращательного движения.

## Возможные проблемы

### Не скачивается модель

Проверьте аргументы `--model-repo` и `--model-file`: имя файла должно точно совпадать с именем файла в репозитории на Hugging Face.

Для моделей с ограниченным доступом задайте `HF_TOKEN`.

### Модель не загружается в память

Уменьшите контекст:

```bash
--n-ctx 2048
```

или используйте модель меньше (например, `1.5B`).

### Слишком много ложных срабатываний плагиата

Увеличьте пороги:

```bash
--sem-threshold 0.85 --lex-threshold 0.55
```

### Слишком мало срабатываний плагиата

Уменьшите пороги:

```bash
--sem-threshold 0.65 --lex-threshold 0.35
```

### Ошибки установки `llama-cpp-python`

Пакет может требовать компилятор.

Для CPU обычно достаточно:

```bash
pip install llama-cpp-python
```

Для CUDA (Linux/macOS, bash):

```bash
CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python --upgrade --force-reinstall --no-cache-dir
```

Для CUDA (Windows PowerShell):

```powershell
$env:CMAKE_ARGS="-DGGML_CUDA=on"
pip install llama-cpp-python --upgrade --force-reinstall --no-cache-dir
```
